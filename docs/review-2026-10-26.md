# QBHive 产品审查报告

> 审查日期：2026-10-26
> 范围：整体业务逻辑、六个菜单（概览/任务/文件/RSS/日志/设置）的实现与交互、各配置项的「新增 → 保存 → 生效」链路
> 依据：全量 Go 后端（`internal/*`，约 6000 行）+ 前端 `web/static/app.js`（1964 行）+ `internal/models/models.go`
> 结论均附 `文件:行号` 证据，便于直接定位

## 总体判断

产品骨架健康：模块边界清晰（RSS / 限速 / 文件管理 / 通知 / 代理各自独立）、后端校验与热重载到位、`saveConfig` 的 `validateConfig` 覆盖面好、`config.Save` 用 `tmp + rename` 原子写、前端有统一的弹窗/toast/分页原语。这些是扎实的部分。

问题集中在**三处结构性缺口**，而非局部 bug：

1. **「保存」语义与用户预期错位** —— 多处配置改完不生效、或生效范围与提示不符，且无未保存守卫。这是最容易被用户感知为「软件坏了」的一类。
2. **后端能力远大于前端暴露面** —— `qb.Client` 已有 `AddTorrent/StopTorrents/StartTorrents`，Web 层一条路由都没开；`filemgr` 全链路不接 `notifier`。产品呈现出的能力只有实际能力的三分之一。
3. **自动化链路缺少「可观测 + 可回退」闭环** —— 归档、删除、后处理这类不可逆动作既不写审计也不发通知，用户无法察觉、无法追溯、无法撤销。

以下按「应当修改调整 / 需要优化 / 建议新增」三类列出，优先级 P0 = 数据丢失或核心功能静默失效，P1 = 明显影响正确性与可用性，P2 = 体验与效率。工作量 S≈半天、M≈1–2 天、L≈3 天以上。

## 四、专项：新增数据的添加流程评估

### 现状链路

| 数据类型 | 入口 | 编辑方式 | 生效动作 | 保存位置 |
|---|---|---|---|---|
| RSS 订阅源 | RSS 页右上角「+ 添加订阅源」（`app.js:814`） | 卡片内联：名称 / 地址 / 开关 | 页面下方「全局设置」卡内「保存」（825） | 全量 POST |
| RSS 匹配规则 | 订阅源卡内「+ 添加规则」（913） | 8 个字段内联 | 同上 | 全量 POST |
| 限速规则 | 设置页「+ 添加规则」（1377） | 5 个字段内联，局部重渲 | 页面最底部「保存全部设置」（1487） | 全量 POST |
| AI 通道 | 设置页「+ 添加通道」（1434） | 5 个字段内联，局部重渲 | 同上 | 全量 POST |
| 清理正则 / 通知渠道 | 设置页 textarea 每行一条 | 纯文本 | 同上 | 全量 POST |

### 共性缺陷

1. **无未保存守卫（O1）** —— 五条链路全部是「编辑本地对象 → 手动保存」，`switchView` 无拦截。这是**当前最高频的数据丢失场景**。
2. **双入口全量覆盖（O2）** —— RSS 页与设置页各自全量读写，互相回滚。
3. **保存动作与编辑动作空间分离** —— RSS 页添加在顶部、保存在中部；设置页保存在 1000+ px 之下。长页面下用户极易「加了就走」。
4. **删除无确认、撤销依赖隐式知识** —— 订阅源/规则/限速规则/AI 通道删除均直接 `splice` 无 `confirmDialog`（对比：审计回退、RSS 重置、批量重命名都有确认）。虽然未保存前刷新可恢复，但用户不知道这一点。
5. **缺必填即时校验** —— 新订阅源 `url` 为空可保存（后端 `server.go:344` 只在非空时校验协议前缀）；新规则的 `include` 为空时靠 `rss.go:613` 兜底不匹配（`Include==""&&Exclude==""` 返回 false，设计正确），但 UI 未说明「只填 Exclude = 匹配除排除外的全部」，有误用风险。
6. **渲染策略不一致（O10）** —— 设置页局部重渲（体验好），RSS 页整页重渲（丢滚动）。

### 建议改造（按性价比排序）

1. **【S】统一 sticky 保存栏 + 未保存指示器**，两页共用同一套组件；脏数据时按钮变主色并有圆点。
2. **【S】切页拦截**：`switchView` 前检查 `_dirty`，提供「保存并离开 / 放弃 / 取消」三选一；同时注册 `beforeunload`。
3. **【S】删除加确认**，并在 toast 里给「撤销」（本地恢复数组项即可，成本极低）。
4. **【M】配置接口模块化**：`POST /api/config/{rss,limiter,filemgr,notifier,qbittorrent,proxy,server}`，后端只合并对应子树 —— 一次性消除全量覆盖问题，也为 N3（导入导出）铺路。
5. **【M】RSS 页改为局部重渲**，新增项后 `scrollIntoView({block:'nearest'})` 并聚焦首个输入框。
6. **【S】必填校验前置**：订阅源 URL 非空、限速规则 match 非空、AI 通道 BaseURL/模型非空（后端已有 `server.go:392-397`，前端应即时提示而非等保存报错）。
